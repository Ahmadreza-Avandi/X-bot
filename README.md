# ربات اتوماسیون پیشرفته X (توییتر) با داشبورد وب و اسکریپت‌های مستقل

این پروژه یک سیستم اتوماسیون کامل برای شبکه اجتماعی X (توییتر) به زبان پایتون است که هم به صورت **داشبورد وب Flask** و هم به صورت **اسکریپت‌های مستقل خط فرمان (CLI)** قابل استفاده است.

---

## 🎯 انتخاب اکانت برای ارسال هر توییت

شما می‌توانید برای هر توییت به صورت مستقل تعیین کنید کدام اکانت آن را ارسال کند:
- **در داشبورد وب:** در تب «ارسال توییت»، منوی کشویی انتخاب اکانت وجود دارد که تمام اکانت‌های تعریف‌شده را با نام، یوزرنیم و وضعیت کوکی نشان می‌دهد. شما اکانت دلخواه را انتخاب کرده و توییت را به صورت «ارسال فوری» یا «افزودن به صف زمان‌بندی» ثبت می‌کنید.
- **در اسکریپت CLI:** با ارسال آرگومان شناسه اکانت (مثلاً `python send_tweets.py acc1`) کوکی همان اکانت لود شده و توییت‌ها از همان حساب ارسال می‌شوند.

---

## 🚀 روش‌های اجرا

### روش ۱: اجرای داشبورد وب
```bash
# نصب وابستگی‌ها
pip install -r requirements.txt
playwright install chromium

# اجرای وب سرور Flask
python app.py
```
سپس در مرورگر به آدرس **`http://localhost:5000`** بروید.

---

### روش ۲: ذخیره کوکی و ارسال مستقیم با CLI

#### ۱. ذخیره کوکی (لاگین تعاملی):
```bash
# برای اکانت پیش‌فرض (cookies.json):
python save_cookies.py

# یا برای اکانت اختصاصی (مثلاً acc1):
python save_cookies.py acc1
```
> در پنجره مرورگر که باز می‌شود لاگین کنید، سپس در ترمینال دکمه `Enter` را بزنید تا کوکی‌ها به طور خودکار استخراج و ذخیره شوند.

#### ۲. ارسال خودکار توییت‌ها از فایل متنی `tweets.txt`:
```bash
# متن توییت‌های خود را سطر به سطر در tweets.txt قرار دهید، سپس اجرا کنید:
python send_tweets.py

# یا با مشخص کردن اکانت:
python send_tweets.py acc1
```

├── data/
│   ├── accounts.json       # لیست حساب‌ها

│   └── index.html          # داشبورد وب مدرن، فارسی، تک‌صفحه‌ای (Vanilla JS)

## 🛡️ جزئیات زنجیره Fallback و ویژگی‌های ضد بن

- **بستن خودکار پاپ‌آپ کوکی:** قبل از کلیک روی کادر، با سلکتور `Refuse non-essential cookies` پاپ‌آپ رد می‌شود.
- **انتخاب مطمئن دکمه Post:** استفاده از `locator('[data-testid="tweetButton"], [data-testid="tweetButtonInline"]').last` برای کلیک دقیق روی دکمه موجود در compose box فعال.
- **تاخیرهای تصادفی:** تاخیر ۱ تا ۲ ساعت بین توییت‌های متوالی (`MIN_DELAY = 3600`, `MAX_DELAY = 7200`) در فایل متنی.
- **تایپ شبه‌انسانی:** تاخیر بین ۵۰ تا ۱۸۰ میلی‌ثانیه برای هر کاراکتر و ۱۰٪ احتمال مکث تفکر بین ۰.۳ تا ۰.۸ ثانیه.
- **پنهان‌سازی شناسه اتوماسیون:** `navigator.webdriver = false` و آرگومان‌های `--disable-blink-features=AutomationControlled`.

## اجرای نسخه فعلی Node.js و اتصال Xray

کد فعلی با Node.js اجرا می‌شود؛ توضیحات Python بالا مربوط به نسخه قدیمی است.

```bash
npm install
npm run dev
```

پنل در `http://localhost:3000` در دسترس است. Chrome/Chromium باید روی سیستم
نصب باشد؛ در صورت نیاز مسیر اجرایی آن را با `CHROME_BIN` مشخص کنید.
برای لینک‌های VLESS، VMess، Trojan، Shadowsocks و پراکسی دارای احراز هویت، باینری رسمی
[Xray-core](https://github.com/XTLS/Xray-core/releases) را نصب کنید و در PATH
قرار دهید یا مسیر آن را با `XRAY_BIN` مشخص کنید. تست اتصال نیز به `curl` نیاز دارد.

- لینک کامل کانفیگ، شامل پارامترهای TLS/Reality، WebSocket یا gRPC حفظ می‌شود.
  انتقال‌های TCP/raw، WS، gRPC، HTTPUpgrade و XHTTP پشتیبانی می‌شوند؛
  فرمت‌های پشتیبانی‌نشده با خطای روشن رد می‌شوند.
- هر کانفیگ حداکثر به سه اکانت قابل تخصیص است. ورود و ارسال هر اکانت از همان
  کانفیگ، از طریق پراکسی SOCKS محلی Xray انجام می‌شود و تونل با بستن مرورگر آزاد می‌شود.
- خطای پراکسی باعث ارسال با IP مستقیم نمی‌شود. مسیر قدیمی ارسال با آدرس ثابت
  GraphQL حذف شده است؛ ارسال از رابط فعلی خود X انجام می‌شود.
- موفقیت فقط پس از دریافت پاسخ CreateTweet و شناسه معتبر ثبت می‌شود. مرورگر تا
  ۴۵ ثانیه منتظر تأیید می‌ماند. خالی‌شدن کادر یا اسکرین‌شات، تأیید انتشار نیست.
  در صورت نبود تأیید، پیش از تلاش مجدد پروفایل را بررسی کنید؛ تکرار خودکار انجام نمی‌شود.
- تست پراکسی درخواست واقعی HTTPS به Google و X را از همان تونل می‌فرستد.
  شکست یا رد درخواست به صورت offline و تأخیر ناموجود نمایش داده می‌شود؛ پینگ ساختگی تولید نمی‌شود.

برای اجرای آزمون‌های رگرسیون محلی (بدون ورود یا انتشار در حساب واقعی):

```bash
npm test
```
